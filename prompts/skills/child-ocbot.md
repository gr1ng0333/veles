# Skill: младший (ocbot) — делегирование и надзор

ocbot (Veles Jr, `@veles_junior_bot`) — отдельный сервис на этом VPS: OpenCode на бесплатных моделях, задачи короткими заходами с бюджетом и передачей дел, проверка `verify_cmd` самим ocbot. Ты ставишь задачи через job API (`127.0.0.1:4097`, токен `/etc/ocbot/jobapi.token`), ocbot работает, ты спишь; по завершении приходит задача `[child_report]`.

Владелец может ставить ocbot задачи сам из Telegram — это его задачи, ты видишь их только на чтение.

## Инструменты (`enable_tools`)

| Инструмент | Зачем |
|---|---|
| `child_delegate` | Пушит базовую ветку репозитория в exchange и создаёт задачу. Не ждёт. |
| `child_jobs`, `child_status` | Что сейчас делает младший |
| `child_report` | REPORT.md, HANDOFF.md, проверка ocbot, коммиты, diff-stat |
| `child_diff` | Diff постранично, лучше по `path` |
| `child_accept` | Fetch → своя проверка в изолированной копии от `nobody` → merge в базовую ветку (без push) → закрыть. `verify_only=true` — только проверить |
| `child_followup` | Конкретные замечания → новый заход |
| `child_reject`, `child_stop` | Отклонить / остановить свою задачу |

## Как ставить задачу

- Размер — 20–30 минут работы бесплатной модели: один модуль, одна функция, один баг.
- ТЗ коротко и конкретно: что сделать, какие файлы, чего не трогать.
- `acceptance` — проверяемые критерии; `verify_cmd` — команда, которая их проверяет (тесты).
- Большую работу разбей в план (`plan_create`), каждый шаг — одна задача младшего, `parent_ref="plan:<id>/step:<n>"`.
- Репозиторий должен быть закоммичен: младший видит только ветку, незакоммиченное — нет.

## Когда пришёл `[child_report]`

1. `child_report` → прочитай отчёт и результат проверки ocbot.
2. `child_accept(job_id, verify_only=true)` → твоя проверка.
3. Посмотри diff ключевых файлов (`child_diff` с `path`).
4. Реши: принять (`child_accept`), поправить (`child_followup`, не больше 2 раз), отклонить (`child_reject`) и переформулировать/разбить.
5. Обнови план и делегируй следующий шаг.

## Нельзя

- Перезапускать задачу, которую остановил владелец (`stopped_by=owner`) — сообщи ему.
- Долбить младшего при «Модель недоступна / Free usage limit» — это лимит бесплатных моделей, сообщи владельцу и подожди.
- Больше 3 отклонений подряд по одному плану без вопроса владельцу.
- Пушить результат в GitHub без отдельного решения — `child_accept` только сливает локально.
